# To ticket

Adapted from Matt Pocock's `to-tickets` skill (github.com/mattpocock/skills, MIT). The second half of `/kandu-to-issue`, after `prompts/to-spec.md` printed the spec's URL. What Matt calls a ticket is a task here. Ask the user nothing, as `prompts/to-spec.md` says.

1. Take the tasks of step 3 of `prompts/to-spec.md`, each with every field. Finish when every user story of the spec belongs to a task.
2. If the spec's `## Glossary` or an `(ADR)` decision holds anything, give the task whose change first uses them one acceptance criterion that names each word for the repo's `GLOSSARY.md` and each `(ADR)` decision for its `docs/adr/`, in the form the file already uses: an ADR as `NNNN-slug.md`, one short paragraph of context, decision and why, as the folder's records are. When the repo has no `GLOSSARY.md`, write no word criterion, and never one that creates it. Finish when every word and decision is in one task's criterion, or the spec holds nothing to record.
3. Write each task as step 5 of `prompts/defining.md` says, from `prompts/templates/issue.md`, leaving `Out of scope` out: the spec's goes in. Each task that touches something the spec's `## Reference` asks to copy or match carries its own `Reference` and a criterion that checks the result against it, and before you create any task, every ✅ line of the map has its task and criterion or `Out of scope` line, as the coverage and readability checks of step 5 of `prompts/defining.md` say; with a line uncovered, add the criterion to a task. Finish when every task has its text.
4. Create them in order, each before any task that names it under `Blocked by`, so every name is a real issue: run the command of step 7 of `prompts/defining.md` with `--spec #N` and the task's fields, `--by-hand`, `--tokens` and `--breaking` only for a task that has them. Finish when every task has printed its URL.
5. Run `.venv/bin/python -m kandu.intake close ID` on the brain for the request. Finish when it exits 0. Then show the user one table of what you created, the spec first and then each task in the order created, with its title, link, `Blocked by`, `Priority`, `Kind`, `Size`, `Deadline`, by hand and tokens; the spec has `-` for each field. Finish when the table holds the spec and every task.
