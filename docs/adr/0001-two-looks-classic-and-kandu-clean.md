# 1. Two looks, Classic and Kandu Clean, chosen per browser

Specs #34 and #40 decided that the dashboard has one look: #34 removed the honeycomb look and the switch between looks, and #40 rebuilt the whole dashboard to the Kandu Clean design. That took away the Classic look the user knew, and spec #52 asks for it back, so each person can use the look they prefer. We replace the "one look" decision: the dashboard has two looks again, Classic and Kandu Clean, each browser chooses between them with a switch and remembers its choice, and a browser that has not chosen opens in the install's default look, Classic when none is set. We keep both because a choice kept per browser lets each person and each device use the look that suits it, while the API, which both looks read, changes only to read and save the default look. The cost is that both looks must show every new warning, task state and action, so each one is added to both; a whole new page goes only into the Kandu Clean look, and the honeycomb look stays gone.
